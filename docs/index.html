Schema Architecture

Authority: 現在の canonical source of truth は src/data-format/schemas/*.schema.json です。v2-alpha.1 の提案は src/data-format/proposals/v2-alpha.1/schemas/ に分離しています。

Proposed schema architecture — v2-alpha.1 design

以下は複数写真、多様な画像形式、usage metadata と technical representation の分離、inline bytes、URI locations、複数 digest / external identifier、および fragmented storage を扱うために検討中の設計で、まだ canonical v1 ではありません。ダイアグラム内のスキーマ名をクリックすると、整形された JSON Schema viewer を開きます。

Metadata axes: display / thumbnail は ImageRepresentationUseV1.purpose が表す usage context です。original / derived は provenance / derivation の別軸なので、この purpose には混在させません。また TagPhotoV1.purpose は「タグにとって論理画像が何を意味するか」を表し、representation-level purpose とは scope が異なります。

ByteSequence model

Digests

その ByteSequenceV1 が表す生 bytes 全体に直接適用した複数の fingerprint。親では whole sequence、fragment の content では fragment bytes だけを対象にします。

Identifiers

ni:, swh: など外部体系で content を識別する URI。

Embedded bytes

document 自体が bytes を包含する場合。JSON では通常 Base64 で符号化します。

Locations

document 外に存在する bytes の URI-reference。HTTPS、相対 URI その他を許容できます。

Fragmented storage

親 ByteSequenceV1 が whole byteLength / digest を保持し、fragmented.fragments[] は offset と nested ByteSequenceV1 を保持します。fragment 側に whole metadata は複製しません。

Fragment validation

fragmented 表現では親と各 fragment の byteLength を schema 上で必須にします。gap / overlap の不存在、全域 coverage、実 bytes と fragment / whole digest の一致は semantic/content validator で検証します。

Same content

inline、location、fragment assembly、digest→CAS のどの経路で得ても、同じ byte sequence なら同一 content とみなします。

Recursive representation

ByteSequenceFragmentV1.content は再び ByteSequenceV1 なので、大きな fragment をさらに分割する多段 fragmented storage も表現できます。

Thumbnail

thumbnail は storage format ではなく ImageRepresentationUseV1.purpose の usage metadata です。実体の mediaType / dimensions は ImageRepresentationV1、inline・外部化・fragmented の選択は ByteSequenceV1 の責務です。
